# SafetyIQ: Industrial Safety and Equipment Documentation Assistant
### RAG · LangChain · OpenAI · ChromaDB · Streamlit

---

## Overview

SafetyIQ is a Retrieval-Augmented Generation (RAG) application that lets engineers query industrial safety and equipment documentation using plain English. Instead of manually searching through hundreds of pages of OSHA standards, API recommended practices, and equipment manuals, engineers ask a question and receive a precise, technically accurate answer with the exact source document and page number cited.

The system retrieves answers only from the loaded documentation corpus. It will not hallucinate answers. If the information is not present in the loaded documents, it says so explicitly. This is a deliberate design choice for a safety-critical domain where fabricated answers are unacceptable.

This directly mirrors a real and active use case in oil refineries and industrial facilities: reducing the time engineers spend manually searching compliance documentation, and making institutional knowledge accessible through natural language.

---

## Problem Statement

Industrial engineers routinely need to look up safety procedures, equipment specifications, and compliance standards scattered across hundreds of PDFs. A refinery may hold thousands of pages of OSHA regulations, API standards, vendor manuals, and internal procedures. Searching manually is slow, error-prone, and depends on the individual knowing where to look.

SafetyIQ addresses this by building a searchable interface over a curated document corpus. It returns grounded answers with source attribution rather than generic LLM responses.

          |
          v

          |
          v
ChromaDB Vector Store (2,254 vectors, persisted to disk)

                    [ Query Time ]

          |
          v
MMR Retriever (fetch_k=20, return k=5, lambda=0.7)

## RAG Pipeline Design Decisions

**MMR retrieval over similarity search**
The retriever uses Maximal Marginal Relevance (MMR) rather than plain cosine similarity. MMR balances relevance to the query against diversity among the retrieved chunks. This prevents the retriever from returning five near-identical chunks from the same paragraph. With a multi-document corpus spanning different document types, MMR ensures retrieval draws from the most relevant sources across the corpus rather than clustering around a single section.

**Constrained prompt with explicit refusal**
The system prompt instructs the LLM to answer only from the provided context and to return a specific refusal message if the answer is not present. This is enforced at `temperature=0`. For a safety and compliance tool, this behaviour is non-negotiable. An LLM confidently fabricating OSHA requirements or equipment pressure ratings is a liability, not a feature.

**Chunk size and overlap**
Chunks are set at 1,000 characters with 200-character overlap. This corresponds to roughly one paragraph per chunk. The overlap prevents key sentences from being severed across chunk boundaries and losing their meaning during retrieval.

**Source attribution**
Every answer is accompanied by the source document filename and page number for each retrieved chunk. Page numbers are adjusted from PyMuPDF's 0-based indexing to match the actual PDF page numbers.

## How to Run

**1. Clone the repository and set up the environment**
```bash
git clone https://github.com/vbharathmohan/safetyiq.git
cd safetyiq
python -m venv safetyiq-env
source safetyiq-env/bin/activate      # Windows: safetyiq-env\Scripts\activate
pip install -r requirements.txt
```

**2. Add your API key**
```bash
cp .env.example .env
# Open .env and add your OpenAI API key
```

**3. Add PDF documents**
Place the six source documents listed in the corpus table above into `data/pdfs/`. Rename them to match the filenames in the project structure.

**4. Run ingestion (one-time)**
```bash
python src/ingest.py
```
This loads all PDFs, splits them into chunks, embeds each chunk using OpenAI, and saves the vector store to `chroma_db/`. This runs once. The vector store persists to disk and does not need to be rebuilt unless the corpus changes.

**5. Launch the app**
```bash
streamlit run app.py
```
Open `http://localhost:8501` in your browser.

## Example Queries

**Single-document retrieval**
> "What are the key elements of a Process Safety Management program?"

Returns a structured answer sourced from OSHA 3132, with pages cited.

**Cross-document retrieval**
> "What are the safety requirements for installing control valves near hazardous areas?"

Returns an answer drawing from both the Emerson Control Valve Handbook and API RP 500, demonstrating retrieval across multiple source documents simultaneously.

**Correct refusal behaviour**
> "What are the inspection intervals for pressure relief valves?"

Returns the explicit refusal message rather than a hallucinated answer, because pressure relief valves are not covered in the loaded corpus.
